# AI 软件测试智能体编排平台 —— 版本规划研发文档

> 本文档为《AI 软件测试智能体工作流编排平台 PRD V1.0》的前端 + 后端研发版本规划。
> 版本号采用**阿拉伯序号**递增（V1 → V12），由易到难、层次递进。
> 每个版本均通过 **Loop Engineering** 方式推进：开发 → 自动打开浏览器验证 → 自动截图 → 发现问题即修复 → 全部通过后再进入下一版本。
>
> 本文档由「需求梳理 → 文档生成 → 逐版本研发 + 自动验证 + 截图 + GitHub 提交」流水线驱动。

## 一、技术架构选型（前后端分离，独立路径）

### 1.0 工程目录约定（强制）

```
ai-test-orchestrator/
├── frontend/   # 前端工程（独立路径，只放前端）
└── backend/    # 后端工程（独立路径，只放后端）
├── docs/       # 文档
└── tests/      # 自动化验证脚本 + 截图
```

后续所有版本的实现都落在对应路径下：前端改动进 `frontend/`，后端改动进 `backend/`，不再混放。

### 1.1 前端技术栈

| 技术 | 用途 | 说明 |
|---|---|---|
| **Vue 3**（`<script setup>` + Composition API） | 视图框架 | 与现有 `frontend/` 工程保持一致，继续推进 |
| **Vite 5** | 构建 / 开发服务器 | 已配置 `/api` 代理到后端 8000 |
| **Tailwind CSS 3**（`polaroid-warm` 拍立得暖色调） | 样式 | 浅色调、暖色卡片，延续现有 Design Token |
| **Pinia** | 状态管理 | 每个模块一个 store |
| **vue-router 4** | 路由 | 11 个模块路由 |
| **@vue-flow/core + background + controls** | 编排画布 | 节点拖拽 / 连线 / 缩放 |
| **axios** | HTTP 客户端 | 调后端 API |
| **ES / JS**（脚本语言） | 语言 | 纯 JS（`.js` / `.vue` SFC） |

### 1.2 后端技术栈

| 技术 | 用途 | 说明 |
|---|---|---|
| **FastAPI + Pydantic v2** | Web 框架 + 数据校验 | 已落地 `backend/main.py` |
| **uvicorn** | ASGI 服务器 | 端口 8000 |
| **Python 3（现有 3.9+）** | 语言 | 后续若升级用 3.10+ 亦可，框架无依赖 |
| **JSON 文件持久化** | 存储 | 可平滑迁移 SQLite |
| **模拟执行引擎** | AI 编排执行 | 拓扑排序 + 模拟推理 + 白名单 + 门禁裁决 + 成本计量 |

### 1.3 AI 技术说明（离线可闭环）

- 当前开发阶段以**模拟执行引擎**串联业务闭环（拓扑排序 + 模拟 AI 推理 + 确定性门禁裁决 + Token/成本计量），保证可离线验证、不依赖外部模型服务。
- 前端「模型配置」展示的模型选项沿用平台约定的**最新模型家族命名**（如 Claude-Opus-4.x / Sonnet-4.x、Gemini-2.x、GPT-4o 等，按上线时最新代次更新），**判定权与叙述权分离、证据优先**原则由引擎落地：
  - 质量门禁 / 计划确认门等关键裁决由**确定性规则引擎**计算，大模型仅生成归因叙述。
  - 工具白名单外的调用在运行时被拦截并记录审计事件。
  - 关键判定字段必须附带证据引用，引擎校验存在性。
- 模型接入层做成**可替换**（接口化），后续无缝切换为真实大模型 API（OpenAI / Anthropic / 通义等），不改动工作流拓扑、数据契约与规则。

## 三、各版本研发细则

### V1 —— 工程骨架 + 工作台总览
- 前端：应用外壳（左侧导航 + 顶栏）；11 个模块路由（未实现的为占位页）；`/dashboard` 完整落地：KPI 卡片（工作流数 / 今日运行 / 通过率 / 本月成本）、最近运行列表、待我处理、典型编排范式入口、平台能力概览。
- 后端：`/api/dashboard/summary` 汇总接口（KPI + 最近运行 + 待办 + 范式）。
- 验证（Playwright 自动开浏览器）：打开 `/dashboard`，核对 KPI / 导航 / 列表，点击导航跳转到各占位页，截图存档。

### V2 —— 工作流列表页
- 前端 `/workflows`：工作流卡片 + 表格，新建 / 重命名 / 删除 / 搜索 / 发布状态切换；5 个 PRD §8 范式模板入口；范式流程预览（节点序列）。
- 后端：工作流 CRUD API（列表 / 新建 / 删除 / 重命名 / 发布）。
- 验证：新建 → 列表刷新 → 重命名 → 删除 → 发布状态切换 → 进入编辑器；截图。

### V3 —— 编排画布（核心强化）
- 前端 `/editor`：完整节点目录（PRD §11 六大类 40 节点，可拖入画布）、端口拖拽连线、数据契约校验、节点配置抽屉（基础信息 / 模型 / 提示词 / 输入绑定 / 输出 Schema / 工具白名单 / 能力包 / 约束 / 规则 / 异步资源 共 10 分区）、结构校验（§7.2 六类规则）、试运行 / 正式运行（画布实时高亮、执行日志）。

## 四、开发与验证规范

### 4.1 Loop Engineering 工作流（每版本）

1. 开发该版本全部功能（含所有小功能）。
2. 启动后端（`uvicorn backend.main:app` :8000）与前端（`vite` :5173）。
3. 用 Playwright **自动打开浏览器**：
   - 逐模块验证每个功能（大功能下的所有小功能都覆盖）；
   - 验证页面跳转与业务串联；
   - 关键步骤**自动截图**保存到 `tests/screenshots/`。
4. 比对截图与需求，发现 bug 立即修复，重复验证，**直到该版本无 bug**。
5. 全部通过后更新 README 与相关文档注释，提交 git（V12 提交 GitHub）。

### 4.2 设计规范
- 整体**浅色调**、**拍立得暖色调**（`polaroid-warm` 色板），延续现有 `frontend/` 风格。
- 布局：左侧导航 + 顶栏 + 内容区；编排画布三区（左节点库 / 中画布 / 右配置抽屉）。
- 风格统一、业务可串联、静态可点击交互跳转。

### 4.3 AI 模型使用说明
- 前后端分离，后端执行引擎负责模拟 AI 节点的编排执行（拓扑排序 + 模拟推理 + 确定性门禁 + 成本计量），保证业务可离线闭环验证。
- 模型命名沿用平台约定的最新模型家族命名；判定权与叙述权分离、证据优先原则落地；可无缝替换真实大模型 API。
